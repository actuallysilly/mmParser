Chapter 12

The trap museum

Every AutoHotkey landmine this repo has actually stepped on, organised by the symptom you will see first. Most of these cost hours. All of them are cheap to recognise once you have seen them named.

Symptom: the script exits with no message

Exit code 0, no dialog, no log line. The nastiest class, because AHK gives you nothing at all.

A variable and a function sharing a name

Trap

AHK identifiers are case-insensitive, so a global _LOG_FORCED and a function _LOG_Forced() are the same name. The script fails to load, exits 0, prints nothing.

Where it bit: core/log.ahk. The cache for the environment override is called _LOG_FORCE_CACHE, with a comment saying it cannot be called _LOG_FORCED because the reader is _LOG_Forced().

How to spot it: if a script stopped loading right after you added a global, check whether any function shares the name ignoring case.

Related red herring: a double comma in InStr(hay, needle, , -1) looks wrong and is fine — it is an omitted optional parameter.

base is a reserved property name

Trap 
o := {base: someValue}      ; does NOT create a property called "base"

It attempts to set the object's prototype, and throws. The failure looked like a script that exited 0 silently.

How it was found: bisecting with FileAppend lines. There is no other way.

Consequence in this repo: the mass record field is ppv_base, never base.

A top-level Integer() on a config value

Trap 
mouseControl := Integer(IniRead(MMA_CFG, "Settings", "MouseControl", 1))

Integer() throws on anything non-numeric, and this runs at the top level. So one hand-edited MouseControl=yes in a file MMA invites you to edit is not a wrong setting — it is a script that does not load.

FileCountConsequence
mass/runtime.ahk9The engine dies → every mass hotkey in MMA is dead.
core/hotkeys.ahk1Every script that binds a key dies.
screen/model_detector.ahk10The detector dies, and it has no window, so there is nothing to notice.

The fix: LOG_IniInt(file, section, key, default, tag) — degrades to the default and says so. Use LOG_IniNum for fractional values; IsInteger("0.30") is false, so LOG_IniInt on a threshold would silently snap every value to its fallback.

#Warn as a hang

Trap

#Warn VarUnset is on by default in v2, fires at LOAD, and a warning is a modal dialog even under /ErrorStdOut.

A test that includes a library expecting globals from its includer hangs forever with no output — which reads as the test passing slowly rather than as a failure.

The fix: #Warn VarUnset, StdOut and assign the globals yourself, so the contract is stated rather than muted. Prefer VarUnset over All, which also prints ~80 "local has the same name as a global" lines and buries the real output.

The bisect technique

FileAppend("reached line 40`n", "D:\bisect.txt")

FileAppend, not MsgBox (which blocks and can itself be the problem) and not LOGI (the logger may be what failed to load). Halve the interval each time.

Symptom: a modal dialog per keystroke

This whole class comes from one fact: #HotIf criteria are re-evaluated on every keypress. Anything a criterion calls is on the typing hot path, and anything that throws there throws once per character.

Reading a global without declaring it

Trap 
ActiveModelNo() {
    Loop MASS_MODELS      ; ← reads an unset LOCAL, and THROWS
        ...
}

In v2 every name inside a function is local unless declared. The global line at the top of these functions is not decoration.

Because ActiveModelStatus is reached from a hotkey context, the throw is one dialog per character typed into a fan's chat.

Any unguarded IniRead conversion in a hot-path function

Same mechanism, different source. DetectorCfg() is reached from #HotIf, and one field — GreyColor, the field a human is most likely to edit by hand — was left going through a raw conversion. "That was not a mis-tuned detector: it was an error dialog per character."

Opening a dialog from a hot-path function

ActiveModelStatus() is deliberately read-only: it never writes an ini and never opens a dialog. The "ask about an unrecognised model name" logic lives in the GUI's process, on a 4-second timer, precisely because a dialog in the resolver would be one popup per keystroke.

Symptom: it works for one item and not the others

The closure family. All three of these produce "the last one wins" or "the loop count is wrong".

A lambda in a loop captures the variable, not the value

Trap 
; WRONG — every key selects model 3
Loop 3 {
    n := A_Index
    HK_Bind("mass.select.m" n, (*) => SelectModel(n))
}

One function body, one n, shared by all three lambdas. By the time any key is pressed the loop has finished.

Two fixes, both used here:

HK_Bind(id, SelectModel.Bind(A_Index))        ; copies the value now

_ModelFire(modelNo, fn) {                     ; a parameter is a fresh binding
    return (*) => (_SetCurModel(modelNo), fn())
}

Where it bit: the [mass.select] keys, and the __1mm…__12mm triggers (all twelve would have meant model 12). tools/test/mass_bind_test.ahk exists to pin it down.

A closure cannot read a for-loop's variables at all

Trap

In for k, v in map, a lambda inside the body cannot see k or v. Copy them to plain locals first.

/validate does not catch this. You find out at run time.

A_Index is the innermost loop

Trap 
Loop MASS_SLOTS {
    for field in MASS_Fields()
        ck := "m" A_Index "_" field    ; ← counts FIELDS (1..44), not slots
}

The inner for has taken over A_Index. This silently built control keys like m17_fu1 that matched nothing, and for the few that did exist wrote one slot's value into another's box.

The tell: loading was broken and saving was fine — which is why it would not reproduce from the save side.

The fix: slot := A_Index before the inner loop.

Symptom: nothing happens, silently

The largest category by far, and the reason log.ahk exists.

A_ScriptDir versus A_LineFile

Trap

A_ScriptDir is the folder of the main script. 37 uses of it worked by coincidence while every entry point lived in the repo root. When entry points moved to subfolders, every IniRead(A_ScriptDir "\cfg", …, default) quietly returned its default.

Use paths.ahk. Never A_ScriptDir.

IniRead with a default cannot fail

Trap

Wrong path, missing section, misspelled key — all return the default, silently. Overload_Mode() read every setting out of a file that did not exist (HK_DIR is the repo root, and no cfg has ever lived there) and returned the default "ask" forever.

The detector: LOG_IniRead writes a VERB line whenever a read falls back. Turn on max logging and grep cfg.

A folder missing from a resolver's list

Trap

MMA_ScriptPath searches a folder list. A folder missing from it means ResolveScriptPath returns "", LaunchStartupScripts skips the entry, and the script simply never starts — no error, no dialog, nothing.

That is how engine.ahk silently stopped running after it moved to src\mass\, and "engine not running" means every mass hotkey is dead.

#HotIf where HotIf() was needed

Trap

#HotIf is a directive that applies to :: hotkeys written literally below it. It has no effect at all on keys registered with the Hotkey() function.

The Discord import was wrapped in #HotIf and bound with Hotkey(), so it was registered globally and fired in every application.

A criterion function with no parameters

Trap

HotIf calls its criterion with the hotkey's name. A zero-parameter function is rejected with "Invalid callback function". Declare every criterion (*) => ….

Same class: a hotkey callback receives the hotkey name, a GUI event handler receives the control and info. Hence DoSomething(*) everywhere.

OnMessage does not keep a script alive

Trap

Neither does a hidden GUI. A v2 script needs a hotkey, a timer, a visible GUI, or Persistent. Otherwise it registers its handler, reaches the end of the file, and exits — leaving no error and no process.

PostMessage's fourth parameter is Control

Trap 
PostMessage(msg, w, l, 0, "ahk_id " hwnd)      ; ✗ "Target window not found"
PostMessage(msg, w, l,  , "ahk_id " hwnd)      ; ✓ omit it

A broadcast that reaches nobody

Trap

HK_Broadcast matches windows whose title starts with HK_DIR. If HK_DIR were src\core\ (this file's own folder) instead of the repo root, the test matches nothing — no script lives there — and every rebind, suspend and remote fire silently stops crossing process boundaries.

The detector: HK_Broadcast logs the recipient count, and a LOGW when it is zero.

Hidden windows are invisible without DetectHiddenWindows

Trap

Every AHK script's main window is hidden. WinExist(path " ahk_class AutoHotkey") returns 0 unless DetectHiddenWindows true is set.

SVC_Running sets it itself rather than relying on the caller having done so, "so a caller that has not cannot get a false 'everything is down'". Always save and restore.

The inverse also bites: with it ON, ahk_exe Discord.exe can resolve to one of Discord's hidden helper windows — blank title, nothing to capture. DiscordChannelName() turns it off for exactly that reason.

Splitting an id at the wrong dot

Trap

[hotstring] ids end in a user-chosen trigger like ..intro. Splitting at the last dot gave section hotstring...intro minus its tail — a section that does not exist — so the key was written in one place and read from another and never fired.

Note the first attempted fix: refusing to bind any trigger containing a dot. That is "a rule about MMA's id format dressed up as a rule about your triggers", and it turned away 23 of them. Worth remembering as a shape of bad fix.

Symptom: the wrong thing happens, confidently

The expensive category, because a plausible wrong answer is acted on.

< and > are numeric and throw on strings

Trap 
if (c >= "a" && c <= "z")     ; ✗ "Expected a Number but got a String"
StrCompare(a, b)              ; ✓

A character-filter loop in next_fu.ahk was written the first way. It did not filter letters — it crashed on the first one. It is a RegExReplace now, which is also faster on a pane's worth of OCR text.

/validate does not catch this.

A Map key that does not exist throws

Trap

m["nope"] throws. It does not return blank. HK_SECTION_LABEL missing an entry raised "key not found" the moment the Hotkeys window reached the first mass.active row.

The pattern that removes the whole class: MASS_Blank() — guarantee every key exists at the boundary, and drop the guards everywhere else.

Assigning an undeclared property silently creates it

Trap

A Gui control has no _v, and AHK will happily create one — so ctrl._v := text succeeds, the box keeps its old text, and nothing anywhere says so. That is why WV_Quiet tests if (cell is WvCell).

A chained ternary has no "else" — it has a last branch

Trap 
slot = 1 ? name1 : slot = 2 ? name2 : name3

answers for slot 4, 5 and 40 with model 3's name. It reads like an enumeration and behaves like a default. Grep for these whenever a bound changes.

One Continue in a bad subscript gives you TWO dialogs

Trap

A single bad array subscript can produce two [Continue][Abort] dialogs. Read pairs in the crash log as one bug, not two, and use mode=Return when scripting around it.

FileOpen eats the BOM; FileRead handles it differently

Trap

Detect a BOM with FileRead(path, "RAW m3"). MMA's message files are mixed BOM and no-BOM, which matters when scanning them as text.

And on the write side: "UTF-8" writes a BOM, "UTF-8-RAW" does not. A BOM is illegal at the start of JSON — Python and browsers reject it outright — which is why MASS_Save uses RAW. AHK never noticed because FileRead(…, "UTF-8") strips one on the way back in.

Escaping order

Trap 
AHK_CHARS := ["``", Chr(34), ";"]   ; backtick MUST be first

Escape the escape character first, or escaping a quote afterwards has its own backtick escaped again.

Ini quirks that change your data

Trap
  • Windows strips leading and trailing whitespace from values, so a separator " | " comes back as "|". MMA encodes spaces as \s.
  • A trailing ; comment on a value line is not stripped — it becomes part of the value.
  • An = in a key is impossible: IniWrite of key a=b emits a=b=value, which reads back as key "a". The guard must live at the two places that write a binding, not at the place that reads them — a check there would be dead code.

Two services writing one file

Trap

Two detectors sharing detector_status.ini would be two services racing over one active_model key, "and the loser wins about half the time — which on this particular key means one model's mass sent into another model's chat."

Hence fansly_status.ini is a separate file, separate readers, and whichever platform's window is in front is the only one consulted.

A normaliser that deletes data outside its shape

Trap 
Loop MASS_MODELS { … }              ; ✗ drops models 4-8 on the next save
keep := Max(MASS_MODELS, src.Length) ; ✓ lowering the count HIDES, never deletes

Any function that rebuilds a structure is a potential data shredder. Ask what it does to data outside the shape it enforces.

Symptom: geometry is off, but self-consistent

Mixed-DPI monitors

Trap

AutoHotkey ships a system-DPI-aware manifest. On a desk where every monitor shares the primary's scaling that is indistinguishable from full awareness. Put a second monitor on a different scale and Windows hands the process invented numbers for window rects, cursor position, the virtual screen, and the origin a BitBlt reads from.

Measured: a box asked for at (−1200, 400) 400×200 landed at (−1008, 545) 480×240. Off by 1.2× in both size and position. SysGet's virtual screen came back 4080×3200 instead of 4080×3840.

Why it is nastier than "20% off": inside the process every wrong number is consistent. The mouse, the overlay and the capture rect agree with each other and disagree only with the screen. Every reading looks plausible.

Two entry points, and picking wrong is the only way to break something: DPI_ScriptWide() for a script whose whole job is pixels (never for one with a normal GUI — its layout is still sized against A_ScreenDPI, which stays the system DPI regardless), and DPI_Enter()/DPI_Leave() paired in a finally for a library included into a GUI process.

Never calibrate from outside AHK

Trap

Do not measure geometry off a PowerShell screenshot or a PrintWindow capture taken by another tool. Different processes have different DPI awareness, so the numbers do not transfer. Measure inside AHK, with the same awareness the consumer will have.

-DPIScale and GUI geometry

Trap

With DPI scaling ON, AHK reports control positions in logical units while the window is created in physical pixels — so on a 125% display rows render 1.25× further down than the layout says. -DPIScale fixes that and means your numbers are real pixels, which then means you must scale: w := w * A_ScreenDPI // 96.

Related: WinGetPos cannot see hidden windows; GetPos/AutoSize under -DPIScale can undersize a window.

Window size assumptions

Trap

All of MMA's automation geometry assumes a 1920×1032 Infloww client. Coordinates in core/coords.ahk, the detector region, the NextFu chat pane and the Discord header band are all measured against that. On a different window size none of them transfer, and each fails differently — the detector reads nothing, NextFu OCRs the wrong pane, the import misses the menu.

CoordMode is thread-global

Trap

Setting it changes behaviour for everything that follows in that thread. Save and restore:

prevPixel := A_CoordModePixel
CoordMode "Pixel", "Client"
...
CoordMode "Pixel", prevPixel

And a maximised window's rect starts at −8,−8 (an invisible border), which is why client coordinates matter for anything measured against a window's chrome.

CAPTUREBLT pulls in your own tooltips

Trap

PILL_Grab deliberately does not set it: it includes layered windows, and MMA's own toast can sit over the tab strip at exactly the moment a select key is pressed.

Bottom-up DIBs read mirrored

Trap

A positive biHeight gives a bottom-up bitmap, so row 0 is the bottom row. Use a negative height for top-down and obvious index arithmetic.

Symptom: it works, then stops working

A stale reading from a polled file

Trap

The detector polls every 500 ms and only while Infloww is focused. So "click a tab, press the key" acted on a reading from before the click — and both models got taught the same x.

The rule: there is no reason to route a measurement you can take directly through a file. TeachPosition reads the pixels at the moment of the press.

The list reorders under a held click

Trap

Infloww sorts conversations by most recent message — and the send that is holding your click is what makes a conversation most recent. A point that meant "Jess, row 4" when you pressed it can mean "Marie, row 4" a second later.

The click wall therefore keeps a bitmap patch of what was under the pointer and compares before playback. Different pixels means the rows moved, and a moved row is not clicked.

A seeded default that outlives its own fix

Trap

AltStageSetting seeds the cfg the first time it reads a key, so changing the fallback in code reaches only brand-new installs. Every machine where a choice has ever been staged already has the old value on disk, and a stored value always wins.

The fix needs an explicit migration — and AltStageMigrateSep replaces only the untouched original. A value somebody deliberately set is left alone.

A stored preference that was never a choice

Trap

Settings writes every key it owns on save, so anyone who has opened Settings once has MainWindowShell=legacy on disk — written by the old default, not chosen. Left alone, "the new default" would have reached new installs only.

MMA.ahk lifts that value once and sets a marker. "The difference between a preference and an inherited default is whether anyone has been asked, and the marker is that question having been asked."

An update that freezes a user-owned file

Trap

The updater skips hotkeys.ini so it cannot overwrite anyone's keys. That alone freezes the file: a key added in a later release is absent, and absent means unbound.

HK_MergeDefaults folds in only what is missing, never touching a key that has a value — including a blank one, so a key you cleared on purpose does not come back to life.

Gitignoring a directory kills negations inside it

Trap 
userdata/          ; ✗ git never descends — the negation below is DEAD
!userdata/hotkeys.default.ini

userdata/*         ; ✓ exclude the CONTENTS, not the directory
!userdata/hotkeys.default.ini

Nobody notices until a fresh clone has no keys to seed from.

Last word. Almost every entry above is written down somewhere in the source, usually as a comment on the line that prevents it. That is the real lesson of this chapter and of this codebase: when you fix something here, the fix is not finished until the comment says what it was. That is what makes the next person — who is you, in six months — able to read the line and not undo it.
