How this works

There is always exactly one root node — the !mma opener. You can't delete it or change its stage.

Every other node sits at a fixed stage: fu1 → fu2 → fu3 → ppv → ppvfu1 → ppvfu2 → ppvfu3, picked from the dropdown in its header. ppvfu1-3 are follow-ups sent after the ppv unlocks. Every stage past root is optional — a flow can skip straight from root to ppv with no fu's, and can end at ppv with no ppvfu's. An edge should always point to a later stage than where it started (shown in red if it doesn't).

Give a node a branch tag (the text box next to the stage dropdown) when it's an alternate version of that stage — e.g. two fu1 nodes, one tagged blue and one tagged yellow, both fed by edges out of root labeled with the client's reply.

Multiple edges out of one node = a fork. Multiple edges into one node = a merge — alternate branches rejoining a shared continuation. A branch can be as short as a single node before merging back.

Hover an edge to see a + button — click it to fork right there: it asks for a branch label and adds a new alternate node at the same next stage, wired from the same source.

Auto layout arranges nodes in columns by stage, git-graph style, with each branch kept in its own lane.

When pasting a plain flat message (no [id]/-> markup), two markers help the parser: a line starting with -- is a comment noting the client's expected reply (stripped, never sent); a lone --- line folds that paragraph into the previous one instead of starting a new stage — e.g. to keep a multi-paragraph ppv as one send instead of spinning off extra ppvfu stages.

The panel on the right mirrors the graph as text — edit it directly or paste a whole new flow in, then hit Apply. Turning that text into hotkeys is a separate step.
